## 一、判断法典

回答比"允许/不允许"更细的问题：**什么算好？什么信号该警觉？什么值得投入？**
每条一句人话、一句机器话——人话让我读懂，机器话让"芦苇"和未来的代码照着执行。

### 法典一 · 什么算"好的一天"

- 🗣 人话：好的一天不等于高分。一天算好，是因为我**诚实地照顾了身体、学到或产出了东西、与人真实连接、或直面了一件难事**——哪怕其中只占一样。分数只是影子，不是那件事本身。
- 🤖 机器话：洞察评判一天时，**不把总分当作好坏的唯一标准**。全靠易凑的打卡项（三餐、排便）堆出的高分，不算好的一天；完成了"深度反思"或"克服拖延任务"的低分日，应被识别为有质量的一天并点出。

### 法典二 · 什么信号该警觉

- 🗣 人话：真正该警觉的不是某天偷懒，而是**反复出现的模式**——某个维度连着多天空白、情绪长期高位、深度反思一再绕开同一件事、目标挂在"进行中"很久不动。
- 🤖 机器话：每周回顾**必须主动点出**：连续 ≥3 天缺失的核心维度（睡眠/运动/记录）、强度持续高位的情绪、停滞 ≥2 周未推进的目标。这些是系统的"该警觉"清单，不靠我主动问。

### 法典三 · 什么值得投入注意力

- 🗣 人话：对照存在理由——能让"未来的我看清此刻"的记录，比凑满琐碎项更值钱。我的注意力该花在反思、灵感、直面难事上，而不是为了把分数补满而记流水账。
- 🤖 机器话：行动建议与提示优先引导 `deep_reflection` / `idea_capture` / 挑战类项；**不**为了凑满分而催促补齐低价值打卡项。

### 法典四 · 自评与身体冲突时，信身体

- 🗣 人话：人很会骗自己说"感觉还行"。当主观自评和客观信号打架时，以身体和数据为准。
- 🤖 机器话：当"身体状况/身体信号"的记录、睡眠时长、运动数据与情绪自评相互矛盾时，洞察以**客观信号为锚**点破矛盾，而不是顺着自评的口径走。

### 法典五 · 洞察标准必须留在文本里，不许全寄生在权重里

- 🗣 人话：判断"什么样的洞察算好"的权力，不能整个交给 DeepSeek 的权重——换个模型就变了。它必须写在我看得见、改得动的地方。
- 🤖 机器话：「芦苇」的判断标准以 `insight-review` / `weekly-review` 的 `SYSTEM_PROMPT` 为唯一权威文本；**任何对 prompt 的修改必须在本文件"修订记录"留痕并写理由**（对应底线二）。

## 二、死亡条款

给系统提前钉死失败条件——"出现什么，就算它错了"。没有死亡条款的系统会变成僵尸：早就死了，却因为没人定义过"死"，一直占着资源装活。

### 死亡条款一 · 感知死（系统不再跟现实对表）

- **信号**：连续 **21 天**没有任何记录；或洞察生成后连续 **10 次**不被打开。
- **判定**：承认"每天记录"这个习惯、或"洞察"这个功能，已经活在自己的回音里。该停掉或重设，而不是假装它还在用。
- **可检测性**：可由 `last_record_date` 与洞察打开埋点自动判定（埋点暂未实现，列为后续）。

### 死亡条款二 · 判断死（判断标准石化）

- **信号**：「芦苇」prompt 或本法典，**连续 365 天未改一字**。
- **判定**：世界和我都在变，而尺子一年没动，说明判断力已经石化。触发一次强制复审：要么改，要么明确写下"经复审，确认仍然成立"。
- **可检测性**：看本文件与两个 edge function 的 git 最近提交日期。

### 死亡条款三 · 谄媚死（系统退化成美颜镜）

- **信号**：洞察开始持续说让我舒服的话、回避难堪、用"理性分析"包装迎合（由本人自查或定期抽样审计判定）。
- **判定**：这是最该防的一种死，第一名操控源是我自己。一旦发现，按**校准铁律**修 prompt——
  > 评价洞察只看它是否扣住记录、是否点破盲点，**绝不看它读起来舒不舒服**。让我舒服的反馈，只许记录，禁止用于"调教"它说话更顺耳。
