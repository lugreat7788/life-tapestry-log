# 生活织锦 · LifeLog

> 一个只为一个人而造的系统：在没有人给我打分的人生里，替我留下一面不说谎的镜子。

我们大多数人，活在别人定义的"什么算对"里——上学有老师打分，上班有老板验收。可一旦走进自己的人生，没有人验收。LifeLog 是我给自己造的第一个验收人：每天记录身体、情绪、学习、关系、目标，让一个叫"芦苇"的 AI 当镜子——不哄我、不夸我，只把我真实活成的样子照给我看。它不让我跑得更快，它让我看得更清。

---

## 创世层

> 这一节刻在石头上，不随版本改。改动它，跑着的就是另一个项目了。

### 一、为什么存在

**为了在没有人给我打分的人生里，替我留下一面不说谎的镜子——让未来的我，能看见此刻的我真实活成了什么样。**

注意：这是"为什么存在"，不是"要做什么"。记录、打分、生成洞察、做统计——那些是会变的*目标*，住在可变层里；存在理由不变。

### 二、死也不越过的底线

违反其中任意一条，它就不再是 LifeLog，只是另一个 App。

**底线一 · 数据只属于我**
- 🗣 人话：个人记录永不用于训练、广告或交给第三方变现，哪怕产品因此长不大、活不下去。
- 🤖 机器话：日志 / 情绪 / 健康数据仅存于用户自己的账户；任何导出、上传、分析只能由用户本人触发；代码里不得出现把原始记录发往非用户控制端点的路径。

**底线二 · AI 永远是镜子，不是回音壁**
- 🗣 人话：洞察只许扣住真实记录、说该说的话；一旦为了让我舒服而粉饰、迎合、空洞鼓励，它就背叛了存在理由。
- 🤖 机器话：「芦苇」系统提示词必须保留三条不可删——镜子定位、禁止空洞鼓励词、一切扣住记录；评价洞察质量只看它是否扣住记录、是否点破盲点，**绝不看它读起来舒不舒服**。

**底线三 · 诚实优先于完整**
- 🗣 人话：宁可某天空着、分数难看，也不假装、不补录、不为凑分而记。
- 🤖 机器话：不提供"一键批量补录历史"的便捷路径；空记录如实呈现为空，不用默认值粉饰；分数只反映真实勾选，不做安慰性向上取整。

> **陌生人测试**：把上面三条给一个完全不认识这个项目的人看，问他——如果违反了这几条，这还是不是 LifeLog？他答得上来，创世层就立住了。

## 还没立的法（下一步）

按《构架师教程：神话时代》的"一部法三块骨头"，这部法还缺两块，留待补全：

- **判断法典** —— 把"什么样的一天算好""什么信号该警觉"从脑子和模型权重里，抠成可读、可改、可审计的文本。目前这部分判断仍部分寄生在 DeepSeek 的权重里（换个模型，同一天记录的洞察可能两样）。
- **死亡条款** —— 定义 LifeLog 自己的失败信号：洞察连续 N 天不被打开（感知死）、prompt 一年未改一字（判断死）、记录沦为应付打卡（谄媚死）。

## 技术

- **前端**：Vite + React + TypeScript + Tailwind + shadcn/ui
- **后端**：Supabase（Auth / Postgres / Edge Functions）
- **AI**：SiliconFlow DeepSeek-V3。"芦苇"洞察在 `supabase/functions/insight-review`（今日洞察）与 `weekly-review`（每周回顾），系统提示词即上文"底线二"约束的对象。
- **部署**：push 到 GitHub `main` → 由 Lovable 自动同步并部署（Edge Functions 部署到 Lovable 托管的 Supabase 项目）。

### 本地开发

```bash
bun install
bun dev        # → vite，本地预览
bun test       # vitest
bun run build  # 生产构建
```
